# Viral formats (live research)

Do **not** rely on a static tip list. Formats change weekly. Before drafting any distribution opportunity:

## Procedure

1. Identify the target **platform** from the Work Order.
2. **Research what is working now** on that platform (web search / browser / recent examples). Prefer patterns from the last 7–30 days over evergreen advice.
3. Pick **one** format that fits the company’s angle and the specific thread/source (if any).
4. Draft to that format only. Ban generic “here’s what we built” pitches unless the chosen format is explicitly a product demo / Show HN / launch maker comment.
5. Return with the opportunity:
   - `format_used` — short name of the pattern (e.g. `hot-take-thread`, `value-first-reddit-comment`, `founder-lesson-li-post`)
   - `format_why` — one line: why this format fits *this week* and *this source*

## Platform hints (starting points — always verify live)

| Platform | Often-working patterns (verify current) |
|----------|----------------------------------------|
| X | Short hot take + proof; reply with a concrete tip; mini thread (hook → story → lesson); demo GIF + one line |
| Reddit | Value-first answer that stands alone; “here’s what worked for me” without linkspam; AMA-style honesty |
| LinkedIn | Specific founder lesson; before/after; question that invites peer stories (no engagement bait) |
| Hacker News | Technical tradeoff; Show HN clarity; no marketing voice |
| Product Hunt | Maker comment / FAQ; honest limitations |
| Discord | Helpful reply in an **opt-in** community thread; never cold DM |

## Hard rules

- Refresh formats **every research run** — do not reuse last month’s template blindly.
- If research tools are unavailable, pick a conservative format, set `format_used` to that name, and say so in `format_why` (`[no live research]`).
- Never invent that a post went viral or that you published.
